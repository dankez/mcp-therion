Following up on my post earlier in the year.

I think I have narrowed to small degree when this problem occurs and at
least found a workaround.

 

The statement;

 

symbol-hide group all

 

was not working for me in one thconfig using all of a largish dataset as
'source', but worked fine in other thconfig files dealing with subsets of
the same dataset.

 

All of my exports refer to a 'LayoutStandard' that contains a line;

 

symbol-show group all

 

This is sometimes countermanded (if for example the output scale will be 1
5000) in a SUBSEQUENTLY called layout by a line;

 

symbol-hide group all

symbol-show <some symbols.>

 

and if I am processing the whole dataset, there are no errors flagged, but
it appears that the 'symbol-hide group all' is being ignored.  (I THINK I
have a good understanding of the order in which layout statements are
processed, because I routinely use multiple layout files, that in turn call
other layouts, often with statements that contradict each other, as a means
of specifying output appearances in a modular manner - no problems except
human error until this).

 

It is strange because if I modify my 'LayoutStandard' to include;

 

symbol-show group all

symbol-hide group all

 

the later statement is correctly processed.

 

So my workaround is to remove the statement 'symbol-show group all' from my
'LayoutStandard' (or from any layout that is to be called).  I guess that
'symbol-show group all' is the default so removing it should not cause
further problems.

 

Seems strange because they work correctly when on consecutive lines, but
fail when called from separate files.

 

Bruce
