def p_continuation_UIS(expr pos,theta,sc,al) =

  U:=(.15u,.3u);

  T:=identity aligned al shifted pos;

  %% draw ? symbol

  pickup PenC;

  thdraw (-.1u,.2u){up}..{down}(.1u,.2u)..{down}(0,-.05u);

  pickup PenX;

  thdraw (0,-.2u);

enddef;

Hi Bruce,
Here is my re-defined p_station code that now works.  For each station that
you want to print the text for, set attr print "true" in the th2 file as I
illustrated in my earlier email.  If you want to turn off printing you can
set the text to "false".  This works for any station, no matter what its
subtype or flags that are set.  The code is as follows:

layout l_p_station_text
 code metapost
  def p_station(expr pos,mark,txt)(text flags) =
      
   % draw default station
   p_station_SKBB(pos, mark, txt, flags);
   
   % now print the text
   if picture(txt):
      picture ATTR__text;
      ATTR__text := txt;
    
      if known(ATTR_print):
        if (ATTR_print="true"):
            if not numeric txt:
                 p_smartlabel(txt,pos);
            else:
                 % draw filled label with text next
                 p_label.urt(ATTR__text,(.5u,-.25u) transformed T,0.0,8);
            fi;
        fi;
      fi;
      save ATTR__text;
    fi;
  enddef;
 endcode   
endlayout

Vasily
The examples you give are for shot flags (duplicate, splay) so they always
apply to pairs of stations.  
Therefore examples like;

flags duplicate 1 at survey
flags not duplicate 2 at survey

are confusing.
I don't think I would find that approach useful as in many (most?) cases you
would need to specify dozens of station pairs.  Generally the existing
syntax is much more compact.

On the other hand it would be a useful addition to the "station flag"
syntax.

In addition to the station command, it would be convenient to be able to set
station flags like we do with the mark command, ie write;

flag [<station list>] <station flag>
flag 42 46 57 doline
flag 27 46 52 60 dig

The existing syntax allows us to specify all the meta data and flags that
apply on a station by station basis.
The syntax above would allow us to specify the stations on a flag by flag
basis, but without the ability to add comments etc.  Notice I have used
'flag' and not 'flags' to distinguish it from the shot flag syntax.

A second thought, why not allow comments and multiple shot flags...

flag [<station list>] [<comment>] <station flag list > 
flag 42 57 "these are all dolines" doline 
flag 27 52 60 "these are all digs" dig
flag 46 "this is a dig in a doline" doline dig

Could be nice?
Would not be high on my personal priority list, but it is something that
from time to time I have wished I could do.

Bruce
