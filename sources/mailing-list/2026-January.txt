Here is the first mapiah release of 2026, the Serra Grande release. * Point height value presumed plus/minus edit support.
* Fixed bugs:
* failure parsing demo file with "Plus number must be positive" parse error.
* parsing/writing '+?' and '-?' values failure for point height -value options.
* Infrastructure maintenance: * Creation of portuguese version of install page.

Happy new year for all,

Hi all,

Complicated subject line, but I'm trying to be too clever and it's _almost_
working but not quite...

All files for this test case are here:
https://drive.google.com/drive/folders/1LUy_q9PMTLYjgSbxqE_3XtzHIpPUojhJ?usp=sharing

Short version: trying to generate LRUD polygons and scaled sketches to one
XVI file doesn't work properly as seen in wrong_positioning_in_xvi.th2.

Long version:
I have a set of (unscaled) sketches. I also have LRUD data. I have scanned
the sketches. I don't want to draw directly on the sketches in xtherion as
the passage widths will be wrong. I have discovered the functionality to
output LRUD polygons as an XVI output which would probably be sufficient,
but I was hoping to get the LRUD polygon output and the morphed sketches to
both appear in the XVI so that I can do the drawing of walls in xtherion
onto that XVI image.

I know about the 'extra' point type, but I haven't used it in these
examples for simplicity.

*Input files:*
1-9p.png - the scan of the sketch
Shredder.th - the th file containing the centerline and LRUDs
Shredder_sketches-1-9p.th2 - a th2 file plotting stations onto the 1-9p.png
image
Shredder.thconfig - a thconfig file that outputs a number of things (using
scale 1:50 because image quality in the morphed sketch is much, much
better):

*Outputs:*
Produced with 'sketches on':
shredder_sketch_plan.xvi
shredder_sketch_plan.pdf
shredder_sketch_plan.th2
shredder_sketch_plan.svg

Produced without 'sketches on':
shredder_lrud-plan.xvi

Now, the shredder_lrud-plan.xvi file works fine, but obviously doesn't
include the sketches.
The shredder_sketch_plan.th2 is a bit useless; the sketch doesn't match up
to the stations and no LRUD polygons are drawn, but I don't really care
about that.
Now the shredder_sketch_plan.pdf and shredder_sketch_plan.svg *actually
work* - the LRUD polygons are drawn over the correctly morphed sketch and
everything lines up. Unfortunately the PDF output is very pale with
yellow-tinted polygons which are a bit tricky to see and obviously going
from PDF back to an image to draw over in xtherion is a faff although very
doable (assuming xtherion doesn't accept PDF as an image format). The SVG
image is darker, but the yellow boxes are not transparent and so obscure
the sketch. Neither have a centerline showing stations, so not useful to
draw on anyway.

The XVI output is much, much better to look at for drawing on - the sketch
appears in detail, and the shaded but transparent blue polygons appear with
a clear centreline. The only issue is that the sketch and the LRUD
polygons/centerlines are misaligned and misscaled, as can be seen in the
file wrong_positioning_in_xvi.th2.

I presume this is _supposed_ to work, since things are correctly aligned in
the SVG and PDF outputs?

Andrew

# Changelog

## 0.2.31 - 2026-01-15 - The [EGB](https://www.egb.org.br) release
* New features:
* Set borders on points (and lines and areas) to show the state of some key options like: mark for line points, visibility for points, lines and areas.
* Presenting orientation and lsize line segment options as arrow at the line point.
* Fixed bugs:
* AppImage lacking settings and icon need for Ubuntu 24.04.
* MacOS dmg file lacking icon.
* Orientation option not being updated when changed from previously set value.
* Changing a PLA type to a hyphenated type throws.
* After unseting an option, it is still shown as yellow (set).
* After unseting a line point option, the line point options window would show options as if there were no line point selected.
* Infrastructure maintenance:
* Removed web version.
* Created THLine._lineSegmentWithSizeOrientationMPIDs and THLine._lineSegmentWithMarkMPIDs to keep track of which line segments have size/orientation and mark options set.
* flutter upgraded to 3.38.7. * flutter pub upgrade --major-versions.

Update - Argh!!  This is frustrating.  It is sort of like the Linux 
version of DLL Hell.

Apparently when I did the system updates a few weeks ago, the tkimg 
package removed itself from tcl 8.6 and added itself to tcl 9.0.  I 
searched through some old emails (lucky I still have them!) and found a 
thread from August 2025.  The solution in that thread was to modify the 
xtherion program so it executed in wish8.6 instead of wish 9.

Repeating my tests from then - I found that package Img is no longer 
available in tcl 8.6.  I changed xtherion to call wish 9.0, and now it 
works.  JPG backgrounds will now load.

The solution in August was to switch to TCL 8.6.  The solution this 
month is to switch to TCL 9.0.   Sheesh ...

bgee at main2:~$ tclsh8.6
% package require Img
can't find package Img
% exit
bgee at main2:~$ tclsh9.0
% package require Img
2.1.0
% exit
bgee at main2:~$
